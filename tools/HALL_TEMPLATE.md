# 店舗追加テンプレート

## 所有者が用意するもの
1. 店舗マップ画像（入口・通路・向きが分かるもの）
2. みんレポの店舗ページURL（/tag/…/）。単日のレポートURLしか分からない場合は担当者が店舗ページを確認する。
3. 台番号のおおよその並び。「左上は101〜120、向かい側は140〜121」程度でよい。欠番は分かる範囲で伝える。

店舗名・地域・画像の確認日も分かる範囲で添える。不明な番号や位置は担当者が確認し、推測を確定情報として公開しない。

## エディター
配置操作は「台番号を入力 → 方向を選択 → 追加ボタン → 画像上をクリック」。X/Yの手入力は不要。店舗情報と画像の縮尺は折りたたみ欄で編集できる。
全体表示と拡大縮小に対応し、列のドラッグは表示倍率に合わせて移動する。「元に戻す」で直前の配置・移動・削除を取り消せる（最大40操作）。
配置と店舗情報は同じ端末・同じブラウザに下書き自動保存する。画像は保存しないため再開時に選び直す。別端末への移動・確実なバックアップにはJSONのダウンロードを使用する。
公開サイトの `/tools/hall-editor.html` を開く。パソコンの広い画面を推奨。
画像を端末内の下敷きにし、台番号の列を追加する。101-120は昇順、120-101は降順、101,102,105は欠番あり。各列のX/Y座標・方向を変更でき、ドラッグ移動もできる。
島の両側は2列で表す。通路は列の間隔で表す。任意の入口アイコン・自由角度の島・複雑な曲線は現版では未対応で、短い列に分けて表す。
画像からの自動OCRではない。画像だけで番号・機種を確定しない。ブラウザからGitHubへの書き込みや公開は行わない。
設定JSONをダウンロードして担当者に渡す。画像は設定に含めず、別途渡す。再編集はJSONを読み込み、画像を選び直す。ブラウザを閉じる前に必ず保存する。

## 担当者の生成操作
`node tools/build-hall.mjs /path/to/店舗設定.json`

`hall-output/店舗ID/` に店舗ページ、店舗JSON、座標JSON、店舗一覧への登録項目、データ収集設定、公開前チェックリストを出力する。
既存の出力先には上書きしない。再生成は `--out /path/to/new-directory` で別フォルダを指定する。
美原の現行ページを共通の雛形として使うため、最新の検索・差枚・狙い台保存・広告設定を引き継ぐ。生成後にそのHTMLだけ編集すると共通雛形との乖離が生じるため、共通改善は雛形側へ反映する。
美原の既存座標とその圧縮表示は維持し、新規店舗は preserve_layout により指定した通路の間隔を保持する。

## 公開と収集
生成は本番登録を行わない。生成先のCHECKLIST.mdに従って配置と台数を照合し、収集用の非公開repoに設定を追加する。
現時点の収集側ワークフローは美原専用。新店舗追加時に `.github/workflows/update.yml` の run.py実行・Validate JSON・Publish JSON の3箇所も新店舗に対応させる必要がある。halls.jsonへの追記だけでは収集されない。このテンプレート導入では収集側の本番処理は変更していない。
公開前に機種名を初回収集データと照合し、draft/noindexを外す。実在しないサンプル店舗は公開しない。
